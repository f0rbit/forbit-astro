# AGENTS.md — forbit-astro

Project-specific conventions and gotchas for agents working in this repo. Stacks on top of the global `~/.claude/AGENTS.md`.

## Lint/format toolchain

Code quality is enforced by `@f0rbit/lint` (oxlint + type-aware ESLint + oxfmt), not prettier.

- Scripts: `bun run lint`, `bun run lint:fix`, `bun run fmt`, `bun run fmt:check`.
- Config: `.oxlintrc.json`, `.oxfmtrc.json`, `eslint.config.ts`.
- `eslint.config.ts` calls `define_lint_config({ naming: "snake_case", tsconfig_root_dir: import.meta.dirname, module_resolution: "bundler", ambient_effect_files: ["src/lib/cache.ts", "src/lib/time.ts", "src/components/blog/PublishTime.tsx"], oxlintrc_path: ..., overrides: [...] })`.
- Format is tabs + 120 width (oxfmt defaults) — NOT the old prettier config (160 width, no semicolons, single quotes). The prettier→oxfmt swap is a breaking formatter change; the repo-wide reformat landed as a standalone Phase 1 commit before any redesign work, so later diffs stay clean.
- `.prettierrc` is deleted; `prettier` and `prettier-plugin-astro` are removed from `package.json`.
- Naming convention: `snake_case` for local variables/functions, `PascalCase` for types/components. **Provider interface methods stay camelCase** (e.g. `listProjects`, `getProject`, `listMyArticles`, `fetchTimeline`) — these are external API contract shapes (`@devpad/api`-style), not free-standing local identifiers, so the naming-convention rule does not (and should not) rename them.

### oxfmt does not format `.astro` files

`oxfmt` only formats `ts/tsx/js/jsx/json/etc` — it does **not** reformat `.astro` files. `.astro` files keep their existing formatting (tabs, quote style, etc. as originally authored) even after `bun run fmt`. Don't expect `fmt:check` diffs inside `.astro` frontmatter/markup from formatting-only issues.

### `.astro` / Solid `.tsx` ESLint coverage

`@f0rbit/eslint-config` only wires up `ts/tsx/mts/cts` extensions, and this repo does not install `astro-eslint-parser`. Consequence: **type-aware ESLint rules never see `.astro` file content** — there was never anything to explicitly "exclude." `oxlint` still lints inside `.astro` frontmatter (e.g. `unicorn/filename-case`, `typescript/no-explicit-any`), so `.astro` files aren't lint-free, just not covered by the _typed_ ESLint layer. Solid `.tsx` files (`SkillSelector.tsx`, `SkillCard.tsx`, `PublishTime.tsx`) go through the normal `ts_files` typed-ESLint path like any other `.tsx`.

### `oxlintrc_path` must point at the canonical oxlint config, not the repo's `.oxlintrc.json`

`eslint-plugin-oxlint`'s rule-dedupe (avoiding double-reporting between oxlint and ESLint) mirrors whatever `files` patterns it finds in the oxlint config it's pointed at. This repo's own `.oxlintrc.json` adds `files`-scoped overrides for `**/*.astro` (to turn off `unicorn/filename-case` there). If `oxlintrc_path` in `eslint.config.ts` pointed at `.oxlintrc.json` directly, the dedupe plugin would inject an ESLint flat-config object scoped to `**/*.astro` — and merely having an `.astro` `files` pattern anywhere in the flat config array makes plain `eslint .` try to parse `.astro` files with the default (non-Astro) parser, which fails immediately with a parse error. Fix: point `oxlintrc_path` at the **canonical** `@f0rbit/oxlint-config/oxlintrc.json` package export (via `createRequire(import.meta.url).resolve(...)`), which has no astro-scoped overrides, so the dedupe stays scoped to `ts_files` as intended. See `eslint.config.ts:24-36`.

### Infra file ignores

`infra.ts`, `pipeline.ts`, `grants.ts` (the pattern used elsewhere in the user's devpad/pipelines stack for files excluded from the TS program) **do not exist in this repo** — there was nothing to ignore for Phase 1. If they're added later (e.g. an Alchemy IaC file), add them to both the ESLint `overrides[].ignores` and mirror in `.oxlintrc.json`, matching the pattern already used for `.astro/**`, `.wrangler/**`, `worker-configuration.d.ts`.

### Scoped lint disables

Every `oxlint-disable-next-line` / `eslint-disable` in this repo carries a reason comment and points at a genuine pre-existing gap — not a convenience silence for something the lint-adoption pass introduced. Current instances: `get_timeline` in `src/utils.ts` (pre-existing `any` params, `@todo fix typings`), untyped `@devpad/api`/dev.to response shapes in `src/providers/*.ts` and `src/lib/build-data.ts`, the Astro middleware's mandated `onRequest` export name, and the ambient `Date.now()`/`new Date()` effects in `src/lib/cache.ts`, `src/lib/time.ts`, and `src/components/blog/PublishTime.tsx` (documented via `ambient_effect_files` in `eslint.config.ts` rather than a disable). Don't add a new disable to silence a rule you tripped — fix it, or defer it explicitly with the same reason-comment convention.

### `fmt:check` ignores `.plans/**`, but not markdown

`.oxfmtrc.json` sets `"ignorePatterns": [".plans/**"]` — plan HTML documents under `.plans/` are working artifacts with their own hand-rolled structure (they're rendered as pages, reviewed in a browser, and follow the canonical `plan-html-template`), not source to be reformatted. `AGENTS.md` (this file) is **not** ignored — oxfmt formats markdown cleanly; the only change it makes is normalizing `*emphasis*` to `_emphasis_`, which is safe. If a future oxfmt run on a markdown file produces a diff that looks like it's mangling content (not just whitespace/emphasis-style), re-evaluate whether that file should move to `ignorePatterns` instead of being auto-formatted.

## Terminal redesign (Tokyo Night theme + shared shell)

- **Design tokens — single source of truth:** the entire palette lives in `src/styles/terminal.css`'s `:root` block. It is intentionally **not** wrapped in `@layer` — `@f0rbit/ui` declares `@layer reset, tokens, components, utilities;` and puts its semantic tokens inside `@layer tokens`; per the CSS Cascade Layers spec, an unlayered rule always beats every layered rule regardless of import order or specificity, so `terminal.css`'s overrides win unconditionally. Shadowed upstream `@f0rbit/ui` tokens: `--bg`, `--bg-alt`, `--border`, `--fg`, `--fg-muted`, `--fg-subtle`, `--fg-faint`, `--accent`, `--font-mono`. Net-new `--term-*` vocabulary: `--term-panel`, `--term-titlebar`, `--term-border`, `--term-border-inner`, `--term-gray-{30,45,58,72,85,97}`, `--term-prompt-user`/`--term-status-finished` (green), `--term-link`/`--term-status-dev` (blue), `--term-keyword` (purple). Never inline an `oklch(...)` literal in a component — add a token to `terminal.css` instead. No webfont: the mono stack is 100% system fonts, so there's no `@font-face`/preload.
- **Shared terminal shell:** `src/lib/path-nav.ts` is the single source of the route→path map (`PATH_TABS`, `is_active_path`, `derive_path`), consumed by `Navigation.astro` (path-nav tab strip + mobile path menu, built on astro-navbar's `Astronav`/`MenuIcon`/`MenuItems`) and `TerminalWindow.astro` (titlebar chrome — traffic-light dots, centered `forbit@dev — {path} — zsh`, right-aligned `<Navigation/>` — defaults `path` to `derive_path(Astro.url.pathname)`). `PromptLine.astro` is the `forbit@dev:<path>$ <cmd>` primitive. `Page.astro` renders every route's content inside `<TerminalWindow>`; SEO/OG/JSON-LD head is untouched.
- **Double nav — resolved:** all 7 route files (`index`, `projects`, `projects/[project_id]`, `about`, `blog`, `blog/[group]/[slug]`, `timeline`) had their redundant page-level `<Navigation/>` calls removed as part of each page's Phase 3 restyle. `TerminalWindow.astro` is now the single place `<Navigation/>` is rendered — verify with `grep -rln "Navigation" src/pages/ src/components/`, which should only match `TerminalWindow.astro`.
- **All pages restyled to the terminal theme (Phase 3):** Home (`src/pages/index.astro`), Projects list + detail (`src/pages/projects.astro`, `src/pages/projects/[project_id].astro`, `ProjectCard.astro`, `components/projects/{ProjectPage,Status}.astro`), About (`src/pages/about.astro`, `components/about/{AboutMe,Experience,ExperienceCard,SkillEvents}.astro`, `components/about/{SkillSelector,SkillCard}.tsx`), Timeline (`src/pages/timeline.astro`, `components/activity/{Timeline,CommitList}.astro`), and Blog list + post (`src/pages/blog.astro`, `src/pages/blog/[group]/[slug].astro`, `components/blog/{BlogCard,RecentBlogs}.astro`) all compose `TerminalWindow`/`PromptLine`/`--term-*` tokens natively — no re-declared chrome, no inline color literals. These were built in parallel worktrees on disjoint file sets and squash-integrated into one commit with zero conflicts.
- **`Experience` variant consolidated:** `Experience.astro`'s `mode` prop was collapsed from a multi-variant union down to a single `mode: "left"` literal (left-border timeline layout) — the only variant either caller (`index.astro`, `about.astro`) used. Widen back to a union if a second layout is ever needed.
- **Lint/format ignores nested worktrees:** `.claude/worktrees/**` (created by parallel `coder-fast` agents) is untracked but not gitignored and lives inside the repo tree, so `oxlint .`/`eslint .`/`oxfmt --check .` from the main tree recursed into sibling worktree checkouts and failed on their differently-versioned toolchains. Fixed by adding `.claude/**` to `ignorePatterns` in `.oxlintrc.json` and `.oxfmtrc.json`, plus an `ignores: [".claude/**"]` override in `eslint.config.ts`. Note: a `src/lib/build-data.ts` unused-eslint-disable failure reported by all five Phase 3 worktrees did **not** reproduce on the main tree's canonical `node_modules` — it was a worktree-local artifact (stale/mismatched installed lint package versions in freshly-bootstrapped worktrees), not a real regression. If it resurfaces on the main tree, treat it as real and fix `src/lib/build-data.ts:21,23`.
- **`astro preview` doesn't work with the Cloudflare adapter:** `@astrojs/cloudflare` explicitly rejects the `astro preview` command. For local visual checks, `bun run build` then `bunx wrangler dev --port 8788` (reads `wrangler.jsonc`'s `assets` binding + `.dev.vars`). If the chrome-devtools MCP's pinned Chromium revision doesn't match what's installed, `bunx playwright install chromium` and drive a small standalone Playwright script instead.
- **Dates — moment.js removed:** replaced by `src/lib/time.ts` (native `Intl` + ms math): `format_duration(start, end)`, `format_relative_time`, `format_calendar`, `format_full_date_time`. Re-exported from `src/utils.ts` as `format_duration` for existing callers. Client-safe (zero deps), so `PublishTime.tsx` (a Solid client island) no longer ships moment to the browser. **Deliberate behavior fix:** old `PublishTime.tsx` used moment's `calendar({ sameElse: "DD/MM/yyyy" })` — lowercase `yyyy` is an invalid moment format token, so it silently rendered the literal string `"DD/MM/yyyy"` for dates more than a week away. The replacement `format_ddmmyyyy` renders a real formatted date — a corrected bug, not a regression.

## Mobile responsive pass (Phase 4)

- **Breakpoint strategy — reuse, never invent:** every responsive rule in this repo keys off the four breakpoints already established by `global.css`'s `.page-container` (640 / 1024 / 1280 / 1700) plus `@f0rbit/ui`'s own `.grid-2/-3/-4` mobile collapse at `max-width: 768px` (an existing upstream breakpoint, not a new one we introduced). Don't add a fifth arbitrary breakpoint — if a component needs to change at a size none of these cover, it's a sign the layout should be rethought around the existing scale first.
- **Grid overflow class of bug — `1fr` tracks don't shrink below content min-width:** any CSS grid track written as bare `1fr` (or `auto 1fr`) sizes its minimum to the content's min-content width by default. Wide, unwrappable card content (long tag lists, badges) can then force the track wider than its share of the container, overflowing a parent with `overflow: hidden` (e.g. `.terminal-window`) even though the *page* never scrolls. Fix pattern: `minmax(0, 1fr)` on every `fr` track that holds card/component content, so the track can shrink and let the content's own wrapping (`flex-wrap`, text reflow) take over. Fixed at: `global.css`'s `.grid-2/-3/-4` override (covers `projects.astro`'s `grid-3`, `about.astro`'s `grid-3`/`grid-4`), `index.astro`'s `.recent-columns` (the desktop bug — `ExperienceCard` clipped on the right edge of the home page's two-column git-log/experience section), `blog.astro`'s `.blog-layout`, `ProjectPage.astro`'s `.project-body`, `AboutMe.astro`'s `.about-me`. When adding a new multi-column grid, default to `minmax(0, 1fr)` rather than bare `1fr` unless the track is a genuinely fixed non-shrinking width (e.g. a sidebar's `280px`).
- **Mobile menu overlay must not be positioned relative to the hamburger button:** `Navigation.astro`'s `.path-menu` (the full-screen `$ cd ~/` mobile menu) is `position: fixed; inset: 0` — NOT `position: absolute` scoped to `.mobile-menu` (the hamburger's own tiny wrapper). An absolutely-positioned overlay inside `.mobile-menu` inherits that element's narrow box as its containing block and renders as a sliver pinned to the button, not a full-screen panel. Because the fixed overlay is a DOM descendant of `.terminal-titlebar` (Navigation renders inside the titlebar), and `.terminal-titlebar` is a positioned ancestor with its own stacking context, the overlay's `z-index` is compared against the titlebar's *other children* (dots, the menu-icon button) within that same local stacking context — not against the titlebar as a whole. So keeping the toggle button (and the traffic-light dots) visible/clickable above the open menu requires those specific elements to carry a higher `z-index` than `.path-menu` (`.terminal-dots` and `.menu-icon` are `z-index: 21` vs `.path-menu`'s `20`, both `position: relative`), not just raising the titlebar's z-index. If you touch this stacking again, verify with an actual screenshot at 360px with the menu open — the sliver bug (menu confined to the button's own hit-box) is easy to reintroduce and easy to miss without visually opening the menu, since layout/typecheck/build all pass regardless.
- **Timeline heatmap on mobile:** wrapped in a `.heatmap-scroll { overflow-x: auto }` container so it degrades to a horizontally-scrollable single-row strip (`flex-wrap: nowrap` + smaller cells) below 640px, instead of the desktop's wrapped multi-row block — its own scroll container, never the page body.
